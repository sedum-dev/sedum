# Core browser observation boundary

Build `@sedum-dev/core` before launching the Playwright driver. The package ships `./page-script.js` as a browser-only IIFE; `PlaywrightBrowserDriver` installs it as a context init script before pages are created. A missing asset produces `script-missing`; a missing or incompatible bridge produces `PageScriptError`.

The versioned `window.__sedum` protocol exposes `collect`, `digest`, `pageVersion`, `quiet`, `findBySignals`, `clickTarget`, `checkAim`, and `clearRefs`. Use the typed functions exported from `@sedum-dev/core` rather than calling the global directly. A collection has a document/route/revision version, total count, and a continuation offset. An incomplete collection is not evidence of absence or a unique cache match. `findBySignals` rescans all eligible candidates; it does not pass an HMAC key into the page. Every rescan invalidates earlier refs. `quiet` reports an observation interval, not final page completion.

`projectCandidates` and `projectDigest` are the SED-12 provider boundary: they only admit the approved fields and reject over-limit or incomplete content. The later provider adapter must enforce the 512-code-point sentence/claim limits and the 64-KiB UTF-8 serialized request limit immediately before the SDK call. Allowed visible text, including secret-looking text, is sent unchanged; do not describe this projection as redaction. Never include internal candidate signals, page versions/routes, selectors, editable values, or raw HTML in a provider request.

`stageEntry`, `pageKey`, and `matchLiveEntry` supply SED-14's transient cache-signal contract. The checkout key is supplied by the later CacheStore implementation; it must be a random 256-bit secret stored in worktree-resolved Git metadata, never in the page script or a provider payload. `stageEntry` requires the complete eligible candidate set, complete bounded item context with a target-specific word, and a unique match. It refuses caching when that evidence is unavailable, even if the page supplies a hook or ID. Call it only after a successful action. Store only `CacheEntry`'s keyed digests and bounded metadata. No entry is a hit until all current eligible candidates are checked. A hit still requires a fresh `clickTarget` aim and `BrowserPage.clickRef` action; a miss remains visible to the caller. For same-frame HTTP(S) links, native navigation is held until the original href and any page cancellation can be checked; download, new-tab, and non-HTTP(S) links are currently non-actionable. Page JavaScript may still initiate its own navigation, so any uncertain outcome is non-retryable. A `clickRef` result with `reason: "action_started"` and `retryable: false` means an event may already have caused an effect: the executor must not repeat the action automatically. SED-24 owns persistence and post-success staging, SED-23 the provider paging/ranking strategy, SED-26 action orchestration, and SED-65 observation retries.
