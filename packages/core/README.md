# Core browser observation boundary

## Flow format boundary (SED-27)

`parseFlow(source, file, { repoRoot })` parses one `*.test.yaml` definition with the `yaml` document AST and a strict v1 schema. `validateFlows` also detects duplicate explicit ids across files. Neither reads environment variables, opens a browser, calls a provider, nor changes the classification cache. A missing `sedum` marker means v1; `sedum: 1` is optional. Diagnostics include `file:line:col`, a code, and a suggested fix. `discoverFlowFiles` recursively finds sorted `*.test.yaml` paths; `loadFlowFile` is the filesystem edge.

The typed definition retains original sentence text, declared `data`, and AST positions. `resolveData(declared, env)` is a separate runtime operation. It supports `$VAR`, `${VAR}`, and `$$` and returns `RuntimeValue` instances with secret provenance. Env-sourced data stays opaque in logs and JSON; only the executor should call `reveal()`. `tokenizeStep` preserves placeholder and quoted-literal spans. After SED-28 classifies a sentence as `type`, it must call `validateTypeOperand` before the step can be considered checked or executed; `resolveTypeOperand` gives the executor an opaque value. The model receives the source sentence with placeholder names, never substituted data values.

## Walking-skeleton runner (SED-19)

`runFlow(file, dependencies)` is the narrow composition boundary behind `sedum
run <file.test.yaml>`. It accepts injected browser, provider, classification
cache, environment, and repository-root dependencies; it does not read process
state or expose SDK/Playwright types. The initial slice supports a flow URL and
ordinary `steps` classified as `type`, `click`, and `verify`. A failed verify
is a test failure; invalid data, browser/provider/locator/action failures, and
unsupported operations are `could_not_run`. `before`, `after`, and modules are
rejected before browser launch pending their owning work. Runtime values remain
opaque outside the executor.

The loader reports `format` coverage and leaves `steps: not_checked`. `classifyParsedFlow` composes the parsed definition with SED-28 classification, static type-operand checking, and source-located diagnostics, marking steps checked only when every sentence succeeds. It marks `modules: not_checked` for any `use:` call, since SED-29 must resolve and validate referenced modules; otherwise modules are `not_needed`. SED-37's `sedum validate` must combine this result with SED-29 module validation before claiming full success. An unresolved sentence, invalid type operand, or unresolved module needs a source-located nonzero diagnostic. `isFullyValidated` encodes this gate for the composed result. SED-19 consumes the typed definition for running tests, with URL/config resolution and runtime environment lookup at that later boundary.

Build `@sedum-dev/core` before launching the Playwright driver. The package ships `./page-script.js` as a browser-only IIFE; `PlaywrightBrowserDriver` installs it as a context init script before pages are created. A missing asset produces `script-missing`; a missing or incompatible bridge produces `PageScriptError`.

The versioned `window.__sedum` protocol exposes `collect`, `digest`, `pageVersion`, `quiet`, `findBySignals`, `clickTarget`, `checkAim`, and `clearRefs`. Use the typed functions exported from `@sedum-dev/core` rather than calling the global directly. A collection has a document/route/revision version, total count, and a continuation offset. An incomplete collection is not evidence of absence or a unique cache match. `findBySignals` rescans all eligible candidates; it does not pass an HMAC key into the page. Every rescan invalidates earlier refs. `quiet` reports an observation interval, not final page completion.

`projectCandidates` and `projectDigest` are the SED-12 provider boundary: they only admit the approved fields and reject over-limit or incomplete content. The later provider adapter must enforce the 512-code-point sentence/claim limits and the 64-KiB UTF-8 serialized request limit immediately before the SDK call. Allowed visible text, including secret-looking text, is sent unchanged; do not describe this projection as redaction. Never include internal candidate signals, page versions/routes, selectors, editable values, or raw HTML in a provider request.

`stageEntry`, `pageKey`, and `matchLiveEntry` supply SED-14's transient cache-signal contract. The checkout key is supplied by the later CacheStore implementation; it must be a random 256-bit secret stored in worktree-resolved Git metadata, never in the page script or a provider payload. `stageEntry` requires the complete eligible candidate set, complete bounded item context with a target-specific word, and a unique match. It refuses caching when that evidence is unavailable, even if the page supplies a hook or ID. Call it only after a successful action. Store only `CacheEntry`'s keyed digests and bounded metadata. No entry is a hit until all current eligible candidates are checked. A hit still requires a fresh `clickTarget` aim and `BrowserPage.clickRef` action; a miss remains visible to the caller. `clickRef` asks Playwright to settle the exact snapshot target without dispatching pointer events, revalidates it after that wait, then delegates actionability, event dispatch, cancellation, and same-frame HTTP(S) navigation to Playwright and the browser. Sedum does not hold or replay a link's default action, and page code may change the result of a native click just as it can for a user. Download, new-tab, and non-HTTP(S) links remain non-actionable because they are outside the current single-page driver contract. A `clickRef` result with `reason: "action_started"` and `retryable: false` means the final click was handed to Playwright but failed, so a page handler may already have caused an effect and the executor must not repeat it automatically. SED-24 owns persistence and post-success staging, SED-23 the provider paging/ranking strategy, SED-26 action orchestration, and SED-65 observation retries.

`executeStep` is SED-26's narrow action boundary. It takes a classified operation and a snapshot-scoped target from the later resolver; it never classifies or re-resolves itself. `type` replaces text with Playwright `fill` on the exact element from a `fill` candidate snapshot, while click reuses PR #2's aim and `clickRef`. Press is page-level and scroll emits one vertical wheel event. A stale target or failed pre-dispatch action is retryable; once browser dispatch may have begun, failure is non-retryable. A click or press compares the immediate page version and settles only a change already observed. SED-65 owns delayed content, fresh observation, and whole-test retry policy. Keep substituted values in `RuntimeValue`/`RuntimeUrl` and route-bearing targets in `ResolvedStepTarget` rather than interpolating them into a command sentence or literal URL; only trusted URL segments and placeholder labels are displayable. Public executor results and errors contain no raw runtime value, full route, Playwright cause, or stack. `goto` uses the driver's safe-diagnostics option, and all uncertain Playwright call-log lines are replaced wholesale.

## Sentence locator

`resolveTarget(page, resolver, { operation, sentence, signal?, timeoutMs? })` accepts `click`, `fill`, or `read` and returns either a `ResolvedStepTarget` or a typed unresolved reason. It performs no browser action. The caller passes its remaining step deadline; SED-65 decides when to retry a stale or incomplete observation. The locator follows every 128-candidate cursor page, requires one stable document/route/revision and an exact total, and stops above 4,096 candidates. Fill first scans only enabled text inputs, textareas, and contenteditable controls that `fillRef` can execute. If that set is empty, a complete click scan supplies diagnostic candidates; a selected label or nonfillable control returns `not_fillable` and is never handed to the fill executor.

Every model Choice includes `none`. Sets larger than 128 are divided into bounded heats; each heat retains its top two non-`none` candidates, including when `none` wins. The locator repeats bounded heats until one final Choice fits, including when valid long Unicode candidate text makes the finalist set too large for one request. Scores from separate heats are never compared. The model request contains only SED-12's approved candidate fields. An over-limit name or peer excerpt returns `request_too_large` before any model call; candidate text is never silently clipped. The adapter remains the final 64-KiB request-size authority.

A selected candidate must clear the confidence and probability-margin gate. Repeated labels or destinations require a distinguishing candidate name or peer phrase in the sentence even when model confidence is high; a generic category or control word alone cannot establish identity. A first-story rank combined with a uniquely matching link purpose can distinguish repeated story links. Low-confidence groups get at most one narrower Choice. Explicit “article body” and “first story” requests require local region/rank evidence even when model confidence is high. After the decision, a full rescan must identify exactly one equivalent live target on the same document and route; a changed route, incomplete scan, or duplicate match returns stale. SED-26 rechecks the returned exact snapshot target immediately before action and never replays an uncertain action. Diagnostics expose only a bounded top-four name/role/probability list, gate reason, candidate count, round count, and provider call metadata; they omit routes, selectors, DOM signals, request bodies, and input values. SED-24 owns cache persistence and SED-39 owns result persistence.

The recorded locator tests run in normal CI. After `pnpm build`, run browser fixtures with `SEDUM_BROWSER_INTEGRATION=1 pnpm exec vitest run packages/core/src/page-script.integration.test.ts`. The optional live target suite uses `SEDUM_LOCATOR_LIVE=1` and `TYPESAFE_API_KEY` to check Saucedemo login and Hacker News with real model calls, and strict candidate-text rejection on Saucedemo's product page and Wikipedia's current Ada Lovelace page. The Wikipedia page currently has over-limit citation text and several indistinguishable article-body Charles Babbage links, so the original PoC sentence is not an actionable target under this contract. The suite prints bounded target and usage evidence without printing the key.
