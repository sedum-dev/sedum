# Core browser observation boundary

Build `@sedum-dev/core` before launching the Playwright driver. The package ships `./page-script.js` as a browser-only IIFE; `PlaywrightBrowserDriver` installs it as a context init script before pages are created. A missing asset produces `script-missing`; a missing or incompatible bridge produces `PageScriptError`.

The versioned `window.__sedum` protocol exposes `collect`, `digest`, `pageVersion`, `quiet`, `findBySignals`, `clickTarget`, `checkAim`, and `clearRefs`. Use the typed functions exported from `@sedum-dev/core` rather than calling the global directly. A collection has a document/route/revision version, total count, and a continuation offset. An incomplete collection is not evidence of absence or a unique cache match. `findBySignals` rescans all eligible candidates; it does not pass an HMAC key into the page. Every rescan invalidates earlier refs. `quiet` reports an observation interval, not final page completion.

`projectCandidates` and `projectDigest` are the SED-12 provider boundary: they only admit the approved fields and reject over-limit or incomplete content. The later provider adapter must enforce the 512-code-point sentence/claim limits and the 64-KiB UTF-8 serialized request limit immediately before the SDK call. Allowed visible text, including secret-looking text, is sent unchanged; do not describe this projection as redaction. Never include internal candidate signals, page versions/routes, selectors, editable values, or raw HTML in a provider request.

`stageEntry`, `pageKey`, and `matchLiveEntry` supply SED-14's transient cache-signal contract. The checkout key is supplied by the later CacheStore implementation; it must be a random 256-bit secret stored in worktree-resolved Git metadata, never in the page script or a provider payload. `stageEntry` requires the complete eligible candidate set, complete bounded item context with a target-specific word, and a unique match. It refuses caching when that evidence is unavailable, even if the page supplies a hook or ID. Call it only after a successful action. Store only `CacheEntry`'s keyed digests and bounded metadata. No entry is a hit until all current eligible candidates are checked. A hit still requires a fresh `clickTarget` aim and `BrowserPage.clickRef` action; a miss remains visible to the caller. `clickRef` asks Playwright to settle the exact snapshot target without dispatching pointer events, revalidates it after that wait, then delegates actionability, event dispatch, cancellation, and same-frame HTTP(S) navigation to Playwright and the browser. Sedum does not hold or replay a link's default action, and page code may change the result of a native click just as it can for a user. Download, new-tab, and non-HTTP(S) links remain non-actionable because they are outside the current single-page driver contract. A `clickRef` result with `reason: "action_started"` and `retryable: false` means the final click was handed to Playwright but failed, so a page handler may already have caused an effect and the executor must not repeat it automatically. SED-24 owns persistence and post-success staging, SED-23 the provider paging/ranking strategy, SED-26 action orchestration, and SED-65 observation retries.

`executeStep` is SED-26's narrow action boundary. It takes a classified operation and a snapshot-scoped target from the later resolver; it never classifies or re-resolves itself. `type` replaces text with Playwright `fill` on the exact element from a `fill` candidate snapshot, while click reuses PR #2's aim and `clickRef`. Press is page-level and scroll emits one vertical wheel event. A stale target or failed pre-dispatch action is retryable; once browser dispatch may have begun, failure is non-retryable. A click or press compares the immediate page version and settles only a change already observed. SED-65 owns delayed content, fresh observation, and whole-test retry policy. Keep substituted values in `RuntimeValue`/`RuntimeUrl` and route-bearing targets in `ResolvedStepTarget` rather than interpolating them into a command sentence or literal URL; only trusted URL segments and placeholder labels are displayable. Public executor results and errors contain no raw runtime value, full route, Playwright cause, or stack. `goto` uses the driver's safe-diagnostics option, and all uncertain Playwright call-log lines are replaced wholesale.
